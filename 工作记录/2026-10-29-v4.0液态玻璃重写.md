## 二、技术路线选择

| 候选 | 结论 |
|------|------|
| 继续用 tkinter 美化 | ❌ 做不出液态玻璃（毛玻璃 / 渐变文字 / blur 光斑都要手绘） |
| PyQt6 | ⚠️ 能做出效果，但依赖 60 MB+，且 QSS 不支持 `backdrop-filter` |
| **pywebview + WebView2** | ✅ 前端就是 HTML/CSS，液态玻璃 CSS 能原样复用；窗口用原生 WebView2，体积可控 |

先做了最小验证：`create_window(js_api=api, frameless=True, easy_drag=True)` +
`window.pywebview.api.ping()` 返回 `pong`，液态玻璃 CSS 在 WebView2 里渲染正常 → 定方案。

## 三、实施过程与踩坑（重点）

### 坑 1：`js_api` 注入失败 —— `api.init is not a function`

现象：界面能渲染，但所有由 JS 生成的内容都没有（操作宫格空、设置开关全关、倒计时不动）。

排查路径：
1. 以为是脚本没加载 → 用 node `--check` 验证语法，通过
2. 以为是缓存 → 改 CSS 不生效，确认 WebView2 缓存了 file:// 资源
3. 在页面里塞了个 `#dbg` 角标，把状态写到 DOM 上，再用 `evaluate_js` 读回来
   （此时 `evaluate_js` 在独立线程里调用，才拿到结果）

**拿到的关键证据**：
```
complete|dbg=BOOT-FAIL TypeError: window.pywebview.api.init is not a function
|bridge=object|hasApi=true|ops=0|err=none|url=http://127.0.0.1:10758/index.html
```

**根因**（读 pywebview 6.2.1 源码确认）：

- `webview/window.py:207` 里 `self.js_api_endpoint = http.global_server.js_api_endpoint
  if http.global_server is not None else None`
- 而 `http.global_server` 在 `webview/__init__.py:274` 才启动，条件是
  `if (http.global_server is None) and (http_server or has_local_urls)`
- `has_local_urls` = 窗口 url 是否本地文件路径

所以：**一旦 `create_window(url="http://...")`，`has_local_urls=False`，
global_server 不启动，`js_api_endpoint=None`，注入的 `api` 是个空对象。**

### 坑 2：`evaluate_js` 两条路都是死路

- **GUI 线程里同步调用** → 与 WebView2 窗口消息泵互锁，整个窗口卡死（实测：日志停在
  「窗口已移动到」之后不再有输出，窗口无响应）
- **独立线程里调用** → 前几次能返回，但后续导致 **python 进程直接退出**（无 traceback，
  日志没有任何退出记录，`Get-Process` 里进程消失）

所以最终**完全不用** `evaluate_js` 做任何数据传递。

### 坑 3：WebView2 缓存旧页面

改了 `index.html` / `app.js` 后重启，界面纹丝不动（连新加的调试元素都看不到）。
file:// 模式下 WebView2 会按 origin 缓存子资源，`private_mode=False` 时尤其明显。

### 最终方案：自建 HTTP 服务

在 `app.py` 里用自己的 `ThreadingTCPServer` 同时提供静态文件和 API：

```python
POST /api/<name>      body: JSON        → Api.<name>(arg) 的返回值
GET  /index.html 等   → SimpleHTTPRequestHandler（web/ 作为 root）
响应头统一 Cache-Control: no-store
```

前端：

```js
async function call(name, arg) {
  const res = await fetch('/api/' + name, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(arg ?? {}),
  });
  return await res.json();
}
```

参数适配规则（`_dispatch`）：

- `{}` → 无参调用（`get_state` / `stop`）
- `{"_arg": X}` → 单值参数（`win('minimize')` / `pick_file('run_program')` / `set_startup(true)`）
- 其它对象 → 整体作为第一个参数（`start(payload)` / `save_prefs(prefs)`）

白名单 `API_WHITELIST` 限定 12 个方法，避免任意属性访问。

### 坑 4：`TCPServer` 单线程导致请求排队

第一版用了 `socketserver.TCPServer`，前端 500ms 轮询 + 我手动 curl 调试 → 请求排队，
外部请求直接超时。改成 `ThreadingTCPServer(daemon_threads=True)` 解决。

### 坑 5：CSS 里 op 按钮文字重叠

`<span class="n">` 和 `<span class="d">` 默认 inline，名称和描述挤在一行
（截图里显示成 `关闭电脑shutdown /s`）。

修复：

```css
.op .txt { flex: 1 1 auto; display: flex; flex-direction: column; align-items: flex-start; }
.op .n, .op .d { display: block; max-width: 100%; }
```

### 坑 6：`conic-gradient` 的 `--p` 不会过渡

自定义属性默认不可过渡，必须先注册：

```css
@property --p { syntax: '<number>'; inherits: false; initial-value: 0; }
```
