# 2026-11-27 关机前预刷卷写缓存（防内核刷盘卡死）

## 起因

用户 2026-11-26 深夜报「强制关机快捷方式双击没反应／还是用不了」，
排查后发现是另一个脚本（`E:\_AI工作记录\设备与系统维护\关机卡住排查\ForceShutdown.ps1`）的问题，
但那轮排查挖出了本机一个确定的硬件事实，值得写进主程序：

**E: 是 TOSHIBA 2TB USB 外置机械盘，F: 是 HSEN 1TB USB 外置盘，闲置后会休眠。**
对休眠中的 USB 盘刷写缓存可以几十秒不返回。

实测证据（`force-shutdown.log`，2026-11-27 02:24:30 用户手动双击留下的）：

```
02:24:30.282  --- 预刷卷写缓存 ---
02:24:31.638    Write-VolumeCache C:  ok  (1,353ms)
02:24:31.831    Write-VolumeCache D:  ok  (190ms)
                ← 到此为止，E: 那行永远没出现
02:24:53.038  用户又点了一次，同样卡在这里
```

而这个「预刷」动作本身是有价值的：本机 2026-11-05 起关机关不掉，
2026-11-06 定案根因是 **C: 卷 NTFS 损坏置脏位 → 关机走到内核 `PopFlushVolumes` 刷所有卷时卡在 Ntfs 上**。
chkdsk 修好后偶发复现。对策就是「在发起 shutdown 之前把各卷写缓存刷干净，让内核那一步无活可干」。

原来这个动作只存在于旁边那个独立的 ps1 脚本里，**主程序（本工具）关机时没有这一步**。
所以本次把它接进主程序，并且按踩过的坑做防护。

## 做了什么

### 新增 `core/preflush.py`

- `_probe_targets()`：用一次 PowerShell 查 `Win32_LogicalDisk` + `Get-Partition|Get-Disk` 拿到每个固定卷的 BusType，
  返回 `[(盘符, 总线类型)]`，**C: 排最前、USB 排最后**。
  探测失败不是错误 —— 降级成「只刷 C:」，因为 C: 才是真正会卡死的系统卷。
- `flush_volumes(include_usb=False, timeout_sec=10)`：
  对每个卷跑 `fsutil.exe volume flush X:`，**跑在独立子进程里带 timeout**；
  超时就杀子进程、记 WARNING、继续下一个卷。任何一块盘都拖不住整个流程。
  **默认跳过 BusType == USB 的卷**（它们不是卡死原因，而且最慢）。
- `run_before_poweroff(...)`：统一入口，异常全吞，绝不允许预刷环节挡住关机。

### 接入 `core/actions.py`

新增 `_preflush_before(operation)`，在 `shutdown()` 与 `restart()` 里、
`safe_close_windows()` 之后、`_run_shutdown()` 之前调用。

**只接了关机与重启**，没接注销/睡眠/关屏 —— 后三者不触发内核刷全部卷，没有这个风险，
多刷一次纯属让用户多等。

### 配置项（`core/config.py` 默认值 + `settings.ini`）

| 键 | 默认 | 说明 |
|---|---|---|
| `preflush_cache` | `true` | 总开关 |
| `preflush_timeout_sec` | `10` | 单卷硬超时（秒） |
| `preflush_include_usb` | `false` | 是否连 USB 外置盘一起刷 |

**未验证**：真正发起关机的那一次没跑（跑就会关机）。所以「预刷 + 关机」的完整串联
只验证到「预刷返回后调用 `_run_shutdown`」这一行之前的全部逻辑；关机本身是否因此不再卡，
要等用户下次真关机才能确认。
