# 2026-10-29 程序图标（v4.0.2）

## 目标

给「定时关机」画一个自己的图标，替掉 PyInstaller 的默认图标。

## 设计

沿用 UI 的设计语言（液态玻璃 + 青紫双色），把界面上那个环形倒计时抽象成一个电源符号：

- **底**：深色玻璃圆角矩形，垂直渐变 `#121b28 → #0b1017`，圆角 206/1024
- **光晕**：中心偏上放一个青色径向光斑（高斯模糊 120px），模拟玻璃后面透出的光
- **符号**：C 形环（缺口在正上方）+ 缺口处一条圆头竖线
  - 环和竖线都用**青→紫对角渐变**（`#6ee7ff` → `#a78bfa`）
  - 弧的两端补了圆形端帽 —— 不加的话 `ImageDraw.arc` 的断口是直角切面，看起来像断层
- **高光**：顶部一条白色 46/255 的模糊横带（玻璃反光），48px 以上才有
- **描边**：1px 白色 38/255 的圆角轮廓

## 三个技术点

### 1. 小尺寸必须单独渲染，不能缩

第一版所有尺寸都从 1024 画布 LANCZOS 缩下去，结果 32px 下环和竖线糊成一坨，
看不出是电源符号；16px 干脆是个蓝块。

改成三套预设，按尺寸切换：

| 预设 | 用于 | ring_w | gap_half | ring_r | margin | halo | gloss |
|------|------|--------|----------|--------|--------|------|-------|
| `std` | ≥48 px | 90 | 21° | 300 | 44 | 0.55 | ✅ |
| `bold` | 32 px | 112 | 27° | 300 | 44 | 0.34 | ✅ |
| `tiny` | 16 / 24 px | 130 | 40° | 330 | 18 | 0 | ❌ |

`tiny` 的思路是：环加粗、缺口开到 40°（否则竖线把缺口堵死）、去掉光晕和高光
（小尺寸下只会变成脏点）、边距缩小让图形占满格子。

（`bold` 现在没在用，留着以备 32px 需要更细的线。）

### 2. Pillow 的 ICO 保存塞不进多种渲染

`Image.save("x.ico", sizes=[...])` 只接受**一张**源图，然后按 sizes 逐个
`thumbnail(LANCZOS)`。这样就没办法让 16px 用 `tiny`、256px 用 `std`。

所以 ICO 是自己拼的，格式很简单：

```
ICONDIR      6 字节：reserved(0) + type(1) + count(N)
ICONDIRENTRY 16 字节 × N：宽 高 调色板 reserved 位深 数据长度 数据偏移
图像数据      各尺寸的 PNG 原始字节（Vista 起支持 PNG 压缩的 ICO 条目）
```

宽高字段是 `uint8`，256 要写 0（这是 ICO 规范里的特殊约定）。

### 3. 环两端的圆头

`ImageDraw.arc(box, start, end, width=w)` 画出来的弧，两端是沿半径方向的**直角切面**。
放大看就是两个斜切口，像被刀切断。

补法：算出两端点在环中心线（`ring_r - width/2`）上的坐标，各画一个直径等于环宽的圆。
这样断口变成圆的，视觉上和整个环连成一根管子。

## 十一、AI 生图候选（同日晚些时候）

自己用 Pillow 画的那版已经够用（v4.0.2 已打包），但用户要求再用 AI 生成两版备选。

### 走过的弯路（记下来免得再踩）

1. **Pollinations.ai**（免费直链生图）—— 现在返回 503 / 402 需要付款，已不可免费用
2. **DSH 内置的 chrome-devtools-mcp 浏览器** —— profile 在 C:\Users\Administrator\.cache\chrome-devtools-mcp\chrome-profile，**没有任何登录态**
3. **Chrome 默认 profile 直连 CDP** —— 从 Chrome 136 起，--remote-debugging-port **只在配合非默认 --user-data-dir 时生效**，用默认 profile 端口根本不绑定（netstat 无监听）
4. **复制 Chrome profile 到临时目录** —— 也不行。新版 Chrome 的 cookie 用 App-Bound Encryption，换了 --user-data-dir 路径后解不开，Gemini 仍未登录

### 最终可行的路

**风之影浏览器（Slimjet 51.0.1.0 / Chromium 149）**，装在 D:\E\风之影浏览器 (64bit)\slimjet.exe，用户数据在 C:\Users\Administrator\AppData\Local\Slimjet\User Data（Cookies 1.5 MB，登录态完整）。

Slimjet 不受 Chrome 那个限制，用**默认 profile + 调试端口**就能开：

    slimjet.exe --remote-debugging-port=9555 --user-data-dir="...Slimjet\User Data" --no-first-run --window-position=-32000,-32000 --window-size=1280,900 about:blank

- **端口不能用 9333** —— 被 G HUB 核心增强插件占了（它从 9333 起自动挑端口）
- --window-position=-32000,-32000 把窗口挪到屏幕外，不占前台
- 用 websocket-client 直连 CDP 操作

### 操作 Gemini 的几个坑

- 只用 Input.insertText 填入的文本，**Angular 不认** —— 发送按钮可点但内部 state 还是空，必须用 document.execCommand('insertText') 才会触发真实 input 事件
- Input.dispatchKeyEvent 发 Enter **不会发送**，必须用 Input.dispatchMouseEvent（mousePressed + mouseReleased）点在发送按钮坐标上
- 发送按钮是 aria-label="发送" 的 button，但**只在有内容时才存在**，要模糊匹配
- 生成结果是 blob: URL，用 canvas toDataURL 导出；直接 fetch blob 拿不到字节
